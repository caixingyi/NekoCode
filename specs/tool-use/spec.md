# 工具系统（Tool Use）需求说明

状态：已确认

## 背景

NekoCode step 1 已完成纯对话内核。step 2 给它装上**工具系统**：用户提问后，模型不再只能输出文本，而是能识别自己要用哪个工具（读文件、写文件、改文件、执行命令、找文件、搜代码），由 NekoCode 执行、把结构化结果回灌进对话，模型据此给出最终回答。这是从「聊天机器人」到「能干活的 Agent」的关键一步。

本步只做**单轮工具调用**：每条用户消息内，模型最多被调用 2 次（首次回复可能含工具调用 → 执行 → 回灌 → 再调一次得最终文本 → 停）。自动连环调用（Agent Loop）留到 step 3。

目标用户：希望 AI 不只是回答、而是能直接在本地项目里读写代码、跑命令的开发者。

## 用户故事

- 作为开发者，我希望 AI 能读取我的文件来理解代码，以便回答基于真实代码的问题。
- 作为开发者，我希望 AI 能改文件、写文件，以便它真正帮我落地改动。
- 作为开发者，我希望 AI 能执行命令（如跑测试、看目录），以便完成需要执行的任务。
- 作为开发者，我希望有副作用的操作（写/改/执行）在执行前让我确认，以便掌控风险。
- 作为开发者，我希望工具出错时模型能看到清晰的错误并调整，而不是整个崩掉。
- 作为开发者，我希望工具只在当前项目目录内活动，以免误伤系统其它文件。

## 需求

### 工具抽象与注册

- R1：定义统一 `Tool` 接口，每个工具实现它，携带元信息：名称、描述、参数 JSON Schema、执行方法。
- R2：一个注册中心集中登记工具，支持按名查找，并能转成各 provider 认得的工具定义列表（Anthropic tools / OpenAI tools）。
- R3：工具执行带超时与错误处理；失败信息包成**结构化结果**（成功/失败标记 + 内容/错误文本）返回给模型，让它能调整而非崩溃。

### 六个核心工具

- R4：`read_file` 读文件内容（超大文件按行截断并提示）。
- R5：`write_file` 写/覆盖文件（有副作用，需确认）。
- R6：`edit_file` 改文件：**原文唯一匹配替换**（给 old/new 字符串）；匹配不到或匹配多次都返回清楚的报错让模型重试（有副作用，需确认）。
- R7：`run_command` 执行 shell 命令（有副作用，需确认；带超时；输出截断）。
- R8：`find_files` 按 glob 模式找文件路径。
- R9：`search_code` 按模式搜代码内容（返回匹配的文件:行:内容）。

### 安全确认

- R10：只读工具（read_file / find_files / search_code）自动执行；有副作用的工具（write_file / edit_file / run_command）执行前需用户确认（y / n / a=本会话全部允许）。
- R11：确认前向用户展示将执行的内容：run_command 展示命令；write_file 展示目标路径与内容预览；edit_file 展示 old/new 的 diff。
- R12：用户拒绝时，返回结构化「用户已拒绝」结果给模型，不执行。

### 作用范围

- R13：文件读写与命令执行都限制在当前工作目录及子目录，拒绝 `../` 越界、cwd 外的绝对路径、以及软链接指向 cwd 外的逃逸，越界返回结构化错误。

### Provider 归一化与流式

- R14：内部消息模型扩展以承载工具调用（tool_use：id/name/input）与工具结果（tool_result：id/content/is_error）；发送时按 provider 归一化（Anthropic content blocks + tool_result；OpenAI tool_calls + role=tool 消息）。
- R15：Provider 请求携带工具定义；解析流式工具调用时拼接分片的 JSON 参数（Anthropic input_json_delta / OpenAI tool_calls.arguments），凑齐后执行；流式期间界面提示正在调用的工具。

### 单轮流程

- R16：每条用户消息最多 2 次 LLM 调用：首次回复（文本 + 可能的 tool_use）→ 执行全部工具（含确认）→ tool_result 回灌 → 再调一次得最终文本 → 停。第 2 次回复里若再出现 tool_use，不执行（那是 loop，留 step 3）。
- R17：一次回复含多个 tool_use 时全部执行，结果一起回灌。
- R18：tool_use 与 tool_result 均持久化进会话，`/resume` 能完整恢复工具往返历史。

### 回答与工具呈现

- R19：助手的最终回复以 Markdown 渲染（标题、列表、代码块、行内代码、引用等），并按终端宽度折行；流式生成期间保持纯文本，该条消息生成结束后再整体渲染一次。
- R20：工具调用与工具结果在会话里以**一行摘要**呈现（调用显示工具名与关键参数；结果显示 ✓/✗ 标记与一行摘要），不把工具完整输出铺满屏幕。完整结果仍随会话持久化并回灌给模型。

## 验收标准

- AC1：问「读一下 X 文件」，模型调用 read_file，回答基于真实文件内容。
- AC2：让 AI 改某文件，edit_file 展示 diff、确认后写入；old 匹配不到/多处时返回清楚报错。
- AC3：让 AI 跑命令，run_command 执行前展示命令并需确认；拒绝时模型收到「已拒绝」并据此回应。
- AC4：一次回复请求多个工具时全部执行、结果一起回灌，得到最终答复。
- AC5：Anthropic 与 OpenAI 两个 profile 都能完成上述工具调用。
- AC6：工具尝试访问 cwd 外路径（`../`、绝对路径或软链接指向 cwd 外）被拒绝，返回结构化错误。
- AC7：命令超时/文件不存在/edit 不匹配等错误以结构化结果回灌，程序不崩溃。
- AC8：含工具往返的会话退出重启 `/resume`，历史（含 tool_use/tool_result）完整恢复。
- AC9：助手回复中的 Markdown（代码块、列表）被正确渲染，且渲染结果不超过当前终端宽度。
- AC10：工具调用以「工具名 + 关键参数」一行展示，工具结果以 ✓/✗ + 一行摘要展示；完整输出不直接铺满屏幕。

## 不做范围

- 自动连环调用（Agent Loop）：模型拿到一次工具结果后停，不自动继续下一轮。
- 子 agent、任务分派、MCP、外部工具协议。
- cwd 限制与确认之外的细粒度权限（如按工具/按路径的 allowlist）。
- 并发执行工具（本步顺序执行）。
- 高级 diff 渲染（语法高亮等），只做朴素 diff。
- 流式生成过程中的实时 Markdown 渲染：流式期间保持纯文本，仅在该条消息生成完成后渲染一次。
- 工具完整输出的展开/折叠查看：会话里只显示一行摘要（R20），需要全文由模型或用户另行读取。
- 欢迎页、提示样式的装饰性外观调整不作为需求条目（属实现细节，见 design.md 影响范围）。

## 约束和假设

- Go 实现，延续 step 1 的 Provider 统一抽象与 bubbletea TUI。
- 工具在本地执行，限于 cwd。
- 需要支持工具调用的模型（Claude 3+ / GPT-4+ 等）。
- 沿用 step 1 的流式、thinking、会话持久化、自动摘要。

## 开放问题（已确认）

- 确认交互：y/n/a（a=本会话全部允许），当前够用，后续不够再扩。
- 默认值：run_command 超时 30s、输出截断约 30KB/200 行；read_file 超大按 ~2000 行截断。
- search_code：用正则。
- run_command 不做危险命令黑名单，靠确认把关。
- 工具默认全开，不做 profile 开关。
